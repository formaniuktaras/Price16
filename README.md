# ProdGen

ProdGen is a desktop application for managing product categories, brands, and models, and for generating listings based on customizable templates.

## Збірка редактора описів

Редактор описів — це окремий фронтенд-проєкт у каталозі `desc-editor`. Нижче наведена покрокова інструкція «для першокласника», яка охоплює всі моменти, де зазвичай щось може піти не так.

### Крок 0. Підготуйте робоче місце

1. **Встановіть Node.js 18+ разом із npm.** Перевірити наявність можна командою `node -v`. Якщо цифра менша за `18.0.0` або команда не знайдена, відвідайте <https://nodejs.org/> і встановіть LTS-версію. Після встановлення перезапустіть термінал.
2. **Переконайтеся, що встановлено Python 3.9+** (сам застосунок написаний на Python). У терміналі виконайте `python --version`. Якщо використовується `py` або `python3`, запишіть, яку саме команду треба використовувати далі.
3. **Встановіть git** (щоб взяти код із репозиторію) та переконайтеся, що ви вже перебуваєте у корені проєкту `Price16`.

### Крок 1. Запустіть майстер збірки

1. У кореневій текі проєкту виконайте одну команду:

   ```bash
   python -m desc_editor_build
   ```

   > Якщо у вашій системі Python запускається через `python3` або `py`, використайте відповідну команду: `python3 -m desc_editor_build` чи `py -m desc_editor_build`.

2. Скрипт **сам** знайде `npm`, перевірить, чи змінювалися файли редактора, та вирішить, що робити далі. Результат видно у виводі:
   - повідомлення `Installing npm dependencies…` означає, що залежності ще не встановлено або вони застаріли;
   - повідомлення `Building production bundle…` сигналізує про запуск `npm run build`;
   - повідомлення `Очищення попередньої збірки…` з’являється, коли скрипт видаляє старий веб-бандл (у тому числі застарілий webviewer) перед створенням нового.

3. Після успішного завершення у папці `desc-editor/dist` з’явиться свіжа збірка з файлом `index.html`. Ці файли використовує десктопний застосунок.

### Крок 2. Що робити, якщо щось пішло не так

| Симптом | Можлива причина | Рішення |
| --- | --- | --- |
| `Помилка: Не знайдено npm...` | Node.js не встановлено або не додано до `PATH`. | Встановіть Node.js 18+, закрийте та знову відкрийте термінал, потім повторіть запуск. Якщо npm встановлено у нестандартній теці, використайте `--npm "C:\Program Files\nodejs\npm.cmd"`. |
| `Команда npm run build завершилася з помилкою` | Похибка в коді редактора або нестача памʼяті. | Прогляньте лог npm (він показується одразу після помилки), виправте причину та повторіть запуск. |
| Потрібно повністю перевстановити залежності | Попередній каталог `node_modules` пошкоджено. | Запустіть `python -m desc_editor_build --force` — скрипт видалить стару збірку, заново поставить пакети та згенерує свіжий бандл. |
| Хочеться подивитися детальний лог npm | У стандартному режимі лог може бути надто стислий. | Запустіть `python -m desc_editor_build --force --skip-install` (якщо залежності вже є) або `python -m desc_editor_build --force` без прапорця `--quiet`. |

### Крок 3. Автоматизація під час роботи застосунку

- Десктопна програма щоразу перед відкриттям редактора викликає `ensure_desc_editor_built()`. Якщо збірка відсутня або застаріла, скрипт автоматично перевстановлює залежності, повністю очищає старий webviewer-бандл і запускає `npm run build`.
- Завдяки службовим «міткам» (`.install-stamp` та `.build-stamp`) наступні запуски займають секунди: якщо файли не змінювалися, кроки `npm install` та `npm run build` пропускаються.
- Для відлагодження можна вимкнути встановлення залежностей (`--skip-install`), обрати власний шлях до `npm` (`--npm /path/to/npm`) або зменшити кількість логів (`--quiet`).

Після виконання цих кроків редактор готовий до використання: відкрийте застосунок (`python main.py`), натисніть **Редактор опису** — і вбудований браузер підвантажить свіжозібраний фронтенд.

## Manual QA
### Підготовка до правильної роботи

1. Потрібно щоб на комп'ютері були встановлені бібліотеки jinja2 та pandas, для цього через powerShell або інший термінал виконайте запити:
  - pip install jinja2
  - pip install pandas
2. Для роботи нового візуального редактора описів переконайтеся, що зібрано веб-фронтенд (див. розділ «Збірка редактора описів» нижче).


### Перейменування з дублікатами

1. Запустіть додаток `python main.py` і переконайтеся, що у каталозі є щонайменше дві категорії (наприклад, «Смартфони» та «Планшети»).
2. Спробуйте перейменувати одну категорію на назву іншої через кнопку **Перейменувати** або через подвійний клік по рядку.
3. Переконайтеся, що з'являється повідомлення «Категорія з такою назвою вже існує» і інтерфейс залишається працездатним.
4. Повторіть ті самі дії для бренду та моделі всередині категорії, щоб впевнитися, що попередження з'являється і таблиці не блокуються.

### Налаштування експорту

1. Перейдіть на вкладку **Експорт** та увімкніть поля, які потрібно бачити у файлі (наприклад, активуйте «Назва_позиції_укр» або додайте власне поле).
2. За потреби відредагуйте шаблон поля, використовуючи доступні змінні (наприклад, `{{ title }}` або `{{ spec('Вага, кг') }}`), та натисніть **Застосувати** → **Зберегти**.
3. На вкладці **Генерація** оберіть декілька моделей і натисніть **Згенерувати**.
4. Відкрийте згенерований файл та переконайтеся, що виведено лише вибрані колонки у потрібному порядку і окремий файл характеристик не створюється.

Ці кроки підтверджують, що попередження про дублікати й надалі працюють, а кастомізація полів експорту дозволяє формувати файл під вимоги різних маркетплейсів без окремого експорту характеристик.
